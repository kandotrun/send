# セキュリティとプライバシー

sendは端末で本文・ファイル・ファイル名を暗号化し、サーバーには暗号文を保存します。これは第三者監査済みという意味ではありません。初期実装のため、公開前の独立レビューが必要です。

## 守るもの
- 正常なクライアントを使用する場合、運営の保存先から本文・ファイル名・内容種別を復号できません。
- 閲覧リンクと管理リンクは独立した秘密を使用し、DBには権限秘密のハッシュだけを保存します。
- 復号鍵はURLの `#` 以降に保持し、HTTP APIのURL・本文・ヘッダーには送信しません。
- metadataとチャンクには転送ID・用途・チャンク順序に結びつく認証を付け、改ざんや別転送の差し替えを拒否します。
- サーバーは失効・期限切れ後の新しい閲覧を拒否します。物理削除は別の処理で、失敗した場合は再試行します。
- アップロード中にisolateが停止するなどして `writing` leaseが未確定のまま残ると、暗号文の物理削除と容量予約の回収は無期限に保留され得ます。アクセス権限の期限切れ・失効は引き続き有効です。これは停止前のPUTが再開してobjectを復活させることを防ぐfail-closed動作であり、通常のGCでは解消できません。

## 守れないもの・残る情報
- 閲覧リンクを知る人は受信でき、リンクを他人へ転送できます。メッセージアプリ等のリンク検査サービスへ渡すことも、そのサービスに秘密を渡すことになります。
- 保存済みの平文や、失効前に開始したダウンロードを回収することはできません。
- 運営が悪意あるJavaScriptを配信した場合、感染端末・悪意ある拡張機能・XSSがある場合、Web E2EEだけでは秘密を守れません。
- ファイルのおおよそのサイズ、期限、通信日時、暗号文、権限ハッシュはサーバーに見えます。CDNは通信元IPを扱います。アプリのレート制限には日替わりHMACで識別したIPを用い、生IPはDBに保存しません。
- ローカルで受信した平文はブラウザのメモリに残り、ダウンロードすると端末にも残ります。リンクは履歴・同期・クリップボードに残り得ます。
- ウイルス検査は行いません。ファイルは自動表示せず、信頼できる送信者のものだけを開いてください。
- 管理リンクをなくすと手動失効できません。復号鍵をなくすと復旧できません。管理リンクだけでは内容を復号できません。

## 公開前ゲート
1. 検証済みのcanonical origin、send専用D1/R2（非公開）、本番secret、実際の予約容量・rate制限を設定する。
2. 期限切れ・不完全アップロード・削除失敗のGCを実リソースで検証し、R2 lifecycleの防御策も設定する。未確定の `writing` leaseを監視し、元のPUTが再開しないことを証明してから物理削除・予約回収する運用手順を検証する。時刻だけでleaseを失効させてはいけない。この回復手順が未承認・未検証なら公開しない。
3. CDN/Worker/backupの保存・ログ保持、Web Analyticsなどの自動注入が無効であることを確認する。秘密やリンク、Authorization、本文はログに出さない。
4. 公開利用規約・プライバシー案内・不正利用の通報先/削除手順を用意する。鍵を持たない運営には内容検査ができない前提で運用する。
5. 独立した暗号/セキュリティレビュー、主要ブラウザと実iPhone、大容量100MB境界を検証する。

`UPLOADS_ENABLED=false` が本番設定の既定です。このPRだけでは公開アップロードを開始しません。
