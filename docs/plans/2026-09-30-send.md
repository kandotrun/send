# send Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Deliver a real local, tested encrypted transfer application and a reviewable GitHub PR, without production deployment.

**Architecture:** Browser Web Crypto encrypts metadata and fixed-size chunks. A same-origin Worker gates immutable encrypted R2 objects with independent capabilities and D1 reservations, expiry and cleanup. Cloudflare cf is the operator CLI, using verified Wrangler delegation for the initial local/bundled configuration.

**Tech Stack:** TypeScript, Web Crypto, Vite, Cloudflare Worker/D1/R2, cf, Vitest, Miniflare, Playwright, Biome, Node 24 LTS (Node22 supported).

---

## Frozen boundaries
`src/shared/protocol.ts` is owned by parent; all workers must follow docs/spec.md and its DTOs. UI imports `createTransfer(input, ttlSeconds, options?)`, `openTransfer(link, options?)`, `getManagement(link)`, `revokeTransfer(link)`, `parseReadLink(url)`, `parseManageLink(url)` from `src/client/transfer.ts` (parse helpers may re-export crypto). All functions use current window origin except parsed URLs; link parsers reject non-current origins in client unless tests explicitly inject a same-origin value. `openTransfer` returns OpenedTransfer and does not download until caller invokes download. All APIs are same-origin with cache no-store.

### Task 1: Crypto/link vertical slice
Files: src/client/crypto.ts, tests/crypto.test.ts. RED: round-trip, wrong key/id/index/tamper, canonical base64url, invalid fragments. GREEN: HKDF, AES-GCM, independent secrets, parsers/builders. Run `npm test -- tests/crypto.test.ts`.

### Task 2: Immutable transfer client
Files: src/client/transfer.ts, tests/client.test.ts. RED: real loopback HTTP observes only ciphertext, no root key or name/text; truncated/swapped chunks rejected, inconsistent server manifest rejected. GREEN: sequential Blob.slice encryption/uploads, publish only after complete, best-effort revoke on canceled/failed upload, no auto replay of single-write chunks. Verify all fixtures reach the actual fetch path.

### Task 3: Storage and authority
Files: migrations/0001.sql, src/worker/*.ts, tests/worker.test.ts. RED: real Miniflare D1/R2 tests for create/upload/complete/read/revoke plus unauthorized seeded state, expired/oversized/malformed and simultaneous create limits. GREEN: guarded SQL reservations/state, byte bounds, hashed capability verification, no raw logs, strict origin and headers. Test completion cannot authorize missing/mutated chunks.

### Task 4: Retention/races
Same backend files. RED: failed R2 delete retains reservation and retry state; overlapping put/revoke/complete/GC cannot restore ready or release twice. GREEN: guards/tombstones/cleanup. Verify real storage state after each operation.

### Task 5: Browser flows
Files: src/web/index.html, src/web/main.ts, src/web/style.css, public/favicon.svg. RED: UI fixture tests before production code, missing labels/drop/status/privacy copy. GREEN: responsive sender, text/file tabs, drag-drop, expiry, progress/cancel, separate read/manage output, receiver and revoke. No plaintext auto-preview of files. Runtime must use frozen transfer client, not fabricated success fixtures.

### Task 6: Real integration gates
